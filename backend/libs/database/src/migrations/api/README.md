# `migrations/api` — the schema history of the Drape API

Every schema change to the Drape database lives here. There is no other mechanism.
`synchronize` is `false` in every environment, without exception (ARCHITECTURE.md §0), so a
column that is not in a migration in this folder does not exist.

Migrations are tracked in the `api_migrations` table (ARCHITECTURE.md §1.1, §2.2).

## Naming

File name:

```
<timestamp>-<PascalCaseName>.ts
```

- `<timestamp>` is epoch **milliseconds**, and it is what orders the run. It is generated by
  the CLI; never hand-edit it and never reuse one.
- `<PascalCaseName>` describes the change in the imperative, e.g. `CreateTryonTables`.

The exported class is `<PascalCaseName><timestamp>` — the same two parts, reversed and
joined, exactly as the CLI emits (ARCHITECTURE.md §2.2):

```
1754300000000-CreateTryonTables.ts   ->   export class CreateTryonTables1754300000000
```

Create them with the scripts, never by hand:

```bash
npm run migration:create   # empty migration, for data changes and hand-written SQL
npm run migration:generate # diff entities against the live schema — ALWAYS review the output
npm run migration:run
npm run migration:revert
npm run migration:show
```

## Rules

1. **Every migration is reversible.** `down()` must perfectly undo `up()` — drop what it
   created, restore what it altered, and drop enum types in the reverse order they were
   created. A migration whose `down()` is empty or throws is not mergeable.
2. **Review every generated migration.** `migration:generate` will happily emit a `DROP
   COLUMN` for a property you renamed. Read the SQL before you commit it.
3. **No destructive migration runs without a verified backup** (PRD E-3). "Destructive" means
   anything that can lose data: `DROP TABLE`, `DROP COLUMN`, `DROP TYPE`, a narrowing
   `ALTER COLUMN TYPE`, a `NOT NULL` added to a populated column, or a `DELETE`/`UPDATE` data
   fix. Verified means a restore was actually performed from that backup — a backup that has
   never been restored is a hypothesis, not a backup (PRD E-15, and the runbook in
   `docs/RUNBOOK.md`).
4. **One migration per logical change.** Do not bundle an unrelated index with a new table.
5. **Quote every identifier.** Columns are camelCase (§2.2) and unquoted identifiers fold to
   lower case in PostgreSQL: write `"deletedAt"`, never `deletedAt`.
6. **Every unique index carries `WHERE "deletedAt" IS NULL`** (§4.0 rule 4). Tables on
   `AppendOnlyEntity` have no `deletedAt` and are the only exception.
7. **Enums are PostgreSQL enum types**, named `snake_case_enum`, with UPPER_SNAKE_CASE values
   identical in TypeScript, PostgreSQL and JSON (§4.1). Create the type before the table and
   drop it after the table in `down()`.
8. **Foreign-key columns are indexed**, and every FK states its `onDelete` (§4.0 rules 8–9).
9. **`AppendOnlyEntity` tables get database-level immutability rules** in the same migration
   that creates them (§2.1):

   ```sql
   CREATE RULE "no_update_quota_ledger" AS ON UPDATE TO "quota_ledger" DO INSTEAD NOTHING;
   CREATE RULE "no_delete_quota_ledger" AS ON DELETE TO "quota_ledger" DO INSTEAD NOTHING;
   ```

   `down()` drops the rules before dropping the table.
10. **Never edit a migration that has run anywhere.** Once it is in `api_migrations` on any
    environment, it is history. Fix it forward with a new migration.

## Skeleton

```typescript
import { MigrationInterface, QueryRunner } from 'typeorm';

export class CreateExampleTable1754300000000 implements MigrationInterface {
  public async up(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`CREATE TYPE "example_state_enum" AS ENUM ('DRAFT', 'PUBLISHED')`);
    await queryRunner.query(`
      CREATE TABLE "examples" (
        "id" UUID NOT NULL DEFAULT gen_random_uuid(),
        "userId" UUID NOT NULL,
        "state" "example_state_enum" NOT NULL DEFAULT 'DRAFT',
        "createdAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
        "updatedAt" TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT now(),
        "deletedAt" TIMESTAMP WITH TIME ZONE,
        CONSTRAINT "PK_examples" PRIMARY KEY ("id"),
        CONSTRAINT "FK_examples_userId" FOREIGN KEY ("userId")
          REFERENCES "users"("id") ON DELETE CASCADE
      )
    `);
    await queryRunner.query(`CREATE INDEX "IDX_examples_userId" ON "examples" ("userId")`);
  }

  public async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.query(`DROP INDEX "IDX_examples_userId"`);
    await queryRunner.query(`DROP TABLE "examples"`);
    await queryRunner.query(`DROP TYPE "example_state_enum"`);
  }
}
```
